## Niat

- Tujuan: Mengunci analisis dua variabel di halaman publik Analisis data: kabupaten × jenis ancaman IRBI/KRB, disilangkan dengan riwayat katalog kejadian dan analogi historis RR/RS/RB. Bukan model kerusakan. Bukan angka meninggal dari skor.
- Berkas: jurnal ini; `docs/pengembangan/STATUS.md`; satu baris di `04-analis.md` dan `03-frontend.md`; `00-protokol.md` Gelombang 22.
- Langkah: tulis keputusan tunggal per butir; baca ulang; jangan mengubah `src/` di tiket ini.
- Cara membuktikan: setiap butir adalah aturan, bukan opsi. FE-27 / AN-33 dapat dijalankan tanpa menebak kelas, skor, atau korban.
- Risiko: menimpa naskah AN-31 (bahaya InaRISK); menjumlahkan IRBI ke KPI kejadian; mengarang zona KRB I/II/III; memakai DIBI sebagai silang kab×jenis.

## Bacaan ulang niat

Satu permukaan: panel terpisah di `/analisis-data`. Sumber IRBI/KRB tidak masuk `buildKejadianAnalisis`. DIBI tetap laci terpisah. Join gagal = null, bukan kelas karangan. Analogi = rentang historis rumah rusak, berlabel bukan prediksi.

## Naskah

### 1. Dua variabel

**Perilaku.** Variabel A = `kab` (nama tampilan kabupaten/kota). Variabel B = `ancaman` (kode `KRB_JENIS_KODE`). Keduanya wajib untuk kartu kelas. Satu variabel saja menampilkan ajakan memilih yang kosong — tanpa kelas.

**Join kab.** `kabupatenNamesMatch` / `lookupIrbiKab` / `lookupKrbKabupaten` / `lookupKrbWilayah`. Kode `11.18` hanya dari baris KRB yang cocok, bukan dari tebakan.

### 2. Pemetaan jenis

**Perilaku.** Helper baru memetakan label kejadian ↔ kode KRB. `juklakToKrbJenis` tetap berdasar kode 101–109; jangan dibalik-paksa. `Gempa Bumi` → `gempabumi`. `Kebakaran Pemukiman` dan `Lainnya` → `null`. `gempabumi` → `["Gempa Bumi"]`. Jenis IRBI tanpa label katalog (likuefaksi, letusan) → daftar kosong.

### 3. Riwayat

**Perilaku.** Riwayat = jumlah baris katalog kejadian berlabel terpetakan di kabupaten itu (jendela `from`/`to` halaman, atau semua jika kosong). Nol = “tidak ada di katalog”, bukan “tidak pernah terjadi”. Tanggal terakhir dari `hari_tanggal` terbaru yang terurai; jika tidak terurai, null.

**DIBI.** `by_kabupaten` tidak memuat jenis. Jangan memakai DIBI sebagai riwayat gempa Pidie Jaya.

### 4. Analogi kerusakan

**Perilaku.** Dari kartu rumah kejadian yang `rr+rs+rb > 0`: min, median, max per tingkat. Grain `kabupaten` jika ada dampak lokal; jika tidak, grain `provinsi` jenis yang sama; jika tetap kosong, `none`. `n` selalu ditampilkan. Jangan mengalikan skor IRBI. Jangan mengisi meninggal/luka dari skor.

### 5. URL dan filter grafik

**Perilaku.** Query `ancaman` hanya kode KRB sah; selain itu dijatuhkan. `jenis` tetap memotong grafik kejadian. Mengisi `jenis` yang terpetakan boleh menyetel `ancaman` default. Mengisi `ancaman` tidak memaksa `jenis` grafik.

### 6. Isolasi angka

**Perilaku.** Skor/kelas IRBI/KRB dan angka DIBI tidak dijumlahkan ke KPI `total` / `impact` katalog. Panel memakai `/api/irbi`, `/api/krb`, dan query kedua `/api/kejadian/analisis` (jenis terpetakan + kabupaten). Tidak ada rute API baru. Tidak ada migrasi.

### 7. Copy kelas

**Perilaku.** Kelas = RENDAH/SEDANG/TINGGI IRBI, bukan zona KRB I/II/III. Jika IRBI dan KRB beda kelas, tampilkan keduanya; jangan dirata-rata. Join gagal = teks “tidak ada baris”, bukan kelas.

### 8. Kasus emas

**Perilaku.** `kab=Pidie Jaya` × `ancaman=gempabumi` → kelas TINGGI, skor 26,4, kode `11.18`. Riwayat gempa di katalog fixture = 0 (ada banjir, bukan gempa). Analogi gempa lokal kosong; analogi provinsi hanya jika ada kartu rumah > 0.

### 9. Non-tujuan

**Perilaku.** Jangan model PAGER/OpenQuake. Jangan angka meninggal dari skor. Jangan query DIBI kab×jenis baru. Jangan mengubah `IrbiHeroPanel` / `KrbHeroPanel`. Jangan menggambar poligon KRB. Jangan DATA-4. Jangan POST nasional. Jangan membuka P2 Juklak.
