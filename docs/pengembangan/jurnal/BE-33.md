# BE-33 — adapter Fonnte/Wablas untuk WHATSAPP_GATEWAY_URL

Agent: backend
Gelombang: tindak lanjut (bukan G35 / G32)
Status: selesai

## Niat

- Tujuan: Klien `sendWhatsAppGateway` berbicara format Fonnte dan Wablas, supaya `WHATSAPP_GATEWAY_URL` yang sudah disebut di dokumen benar-benar mengirim Daily Brief + laporan. Bukan akun baru di git. Bukan rute publik baru. Bukan Z-API / Python / OTP.
- Berkas: `src/lib/laporan/whatsapp.ts`, `src/lib/laporan/whatsapp.test.ts`, `src/lib/security/production-config.ts`, `.env.example`, `docs/laporan-production.md`, `docs/vercel.md`, jurnal ini, baris STATUS.
- Tidak diubah: template pesan `daily_brief` / laporan; cron secret; tabel `daily_brief_*`; `notifikasi_wa`; AN-36; FE-43/FE-44; DATA-4.
- Langkah: uji murni pemetaan URL→header/body; Fonnte = `target` + Authorization mentah; Wablas = `phone` + Authorization mentah; URL lain tetap `{ phone, message, text }` + Bearer; peringatan produksi jika URL kosong; contoh URL publik di docs (bukan token).
- Cara membuktikan: `node --import tsx --test src/lib/laporan/whatsapp.test.ts`; `tsc --noEmit` pada berkas itu. Jangan POST ke Fonnte. Jangan menulis nilai token.
- Risiko: menempel URL Fonnte tanpa adapter (gagal); mengarang nomor perangkat; membuka endpoint publik `/api/whatsapp`.

## Bacaan ulang niat

`WHATSAPP_GATEWAY_URL` adalah alamat layanan pengirim, bukan secret yang digenerate di Vercel. URL Fonnte yang sah = `https://api.fonnte.com/send` (publik). Token tetap dari dashboard Fonnte setelah HP pengirim dipasangkan — tiket ini tidak membuat akun. Payload aplikasi hari ini (`phone` + `Bearer`) tidak cocok Fonnte (`target` + token mentah); tanpa adapter, produksi tetap `failed`. Satu umpan mati tidak diisi dari umpan lain. G32 LLM tidak dibuka.
