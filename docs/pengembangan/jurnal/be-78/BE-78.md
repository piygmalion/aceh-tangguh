# BE-78 — pg_cron primer untuk refresh overlay live

Agent: backend
Gelombang: kemudian
Status: draf

## Niat

- Tujuan: Jadwal GitHub `overlay-live-refresh.yml` (`*/15`) sering terlambat 2–6 jam, sementara baris overlay kedaluwarsa setelah 2 jam (`OVERLAY_WEATHER_LIKE_TTL_MS`). Kartu live jadi tidak tersedia di antara jalan. Penjadwal primer pindah ke `pg_cron` di Postgres, setiap 15 menit, memanggil `POST https://aceh-tangguh.vercel.app/api/cron/overlay-live`. Workflow GitHub tetap sebagai cadangan. Migrasi tidak diterapkan ke basis data hidup dari tiket ini.
- Berkas:
  - `supabase/migrations/20261027_overlay_live_pg_cron.sql` (baru)
  - `.github/workflows/overlay-live-refresh.yml` (hanya komentar: pg_cron primer)
  - `src/lib/overlay-live-pg-cron.test.ts` (baru; kontrak berkas)
  - jurnal ini
  - satu baris `docs/pengembangan/STATUS.md`
- Tidak diubah: env, `vercel.json`, fixture, UI, rute cron, `weather-refresh.yml`, `sipongi-refresh.yml`, migrasi lama.
- Langkah:
  1. `create extension if not exists pg_net` di skema `extensions`, lalu `pg_cron` di skema `pg_catalog` (pola pemasangan Supabase).
  2. Cabut jadwal lama bernama `overlay-live-refresh` bila ada, lalu jadwalkan ulang `*/15 * * * *`.
  3. Perintah job membaca `select decrypted_secret from vault.decrypted_secrets where name = 'overlay_cron_secret'` saat jalan. Header `Authorization: Bearer` memakai nilai itu. Tidak ada rahasia di berkas.
  4. Jika baris Vault kosong, null, atau hanya spasi, job kembali tanpa `net.http_post`.
  5. `timeout_milliseconds` 70000, di atas `maxDuration` rute (60 detik) dan di bawah batas panduan cron Supabase (10 menit).
- Cara membuktikan: uji kontrak berkas; `tsc`, `lint`, `build`, `npm test`. Tidak ada `supabase db push`, SQL editor produksi, atau POST ke cron.
- Risiko: Job dan Actions bisa jalan bersamaan. Refresh menimpa baris live; bukan migrasi data. `pg_net` sempat menulis header (termasuk Bearer) di `net.http_request_queue` sampai permintaan terkirim. Jangan SELECT antrean itu ke log. `docs/vercel.md` bagian 4 masih menyebut cron overlay tetap di GitHub Actions; berkas itu di luar tiket ini.

## Bacaan ulang niat

Niat bisa dijalankan tanpa menebak Tatonas, zona KRB, atau angka korban, dan tanpa menulis nilai `OVERLAY_CRON_SECRET`. Path dicek di `src/app/api/cron/overlay-live/route.ts` (`POST`, Bearer `OVERLAY_CRON_SECRET`). URL produksi sama dengan `docs/vercel.md`. Rahasia hanya nama Vault `overlay_cron_secret`. Basis data hidup tidak disentuh. Workflow cuaca dan Sipongi hanya dilaporkan.
