## Niat

- Tujuan: Jadwal GitHub `weather-refresh.yml` (`0 */3 * * *`) sering terlewat berjam-jam, sementara `POST /api/weather/refresh` menulis `expires_at` = sekarang + 4 jam. Penjadwal primer pindah ke `pg_cron`, job `weather-refresh-hourly`, `7 * * * *` (menit 7, supaya tidak bertabrakan dengan job overlay `*/15`). Job memanggil `POST https://aceh-tangguh.vercel.app/api/weather/refresh`. Workflow GitHub tetap cadangan: `workflow_dispatch` plus jadwal lambat `0 */6 * * *`. Migrasi tidak diterapkan ke basis data hidup dari tiket ini.
- Berkas:
  - `supabase/migrations/20261029_weather_refresh_cron.sql` (baru)
  - `.github/workflows/weather-refresh.yml` (jadwal cadangan 6 jam; komentar pg_cron primer)
  - `src/lib/weather-refresh-pg-cron.test.ts` (baru; kontrak berkas)
  - `src/lib/weather/cache-read.test.ts` dan `src/lib/weather/weather-refresh-failure.test.ts` (kunci jadwal 3 jam diganti kunci jadwal baru)
  - jurnal ini
  - satu baris `docs/pengembangan/STATUS.md`
- Tidak diubah: rute refresh, env, `vercel.json`, fixture, UI, migrasi lama, `overlay-live-refresh.yml`, `sipongi-refresh.yml`, basis data hidup.
- Langkah:
  1. Salin pola `20261027_overlay_live_pg_cron.sql`: `pg_net` di skema `extensions`, `pg_cron` di skema `pg_catalog`, keduanya `if not exists`; hak `cron` untuk `postgres`; `cron.unschedule` menurut nama job lalu `cron.schedule`.
  2. Nama job `weather-refresh-hourly`, jadwal `7 * * * *`.
  3. Jika Vault `weather_cron_secret` hilang, null, atau hanya spasi, job `return` tanpa `net.http_post`.
  4. Header `Authorization: Bearer` memakai `btrim(decrypted_secret)`. Newline di ujung nilai Vault membuat rute membalas 401.
  5. `timeout_milliseconds` 70000. Badan `{}`. URL produksi `/api/weather/refresh`.
  6. Rollback dikomentari di akhir berkas: `cron.unschedule` untuk nama job yang sama. Jangan `drop extension`.
- Cara membuktikan: uji kontrak berkas; `npm test`; `npx tsc --noEmit`. Tidak ada `supabase db push`, SQL editor produksi, atau POST ke cron.
- Risiko: Job pg_cron dan Actions bisa jalan berdekatan tiap 6 jam (menit 0 vs menit 7). Keduanya menimpa baris `weather_forecasts`; bukan migrasi data. `pg_net` sempat menulis header (termasuk Bearer) di `net.http_request_queue` sampai permintaan terkirim. Jangan SELECT antrean itu ke log. `docs/vercel.md` §4 masih menyebut cron cuaca tetap di GitHub Actions; berkas itu di luar tiket ini.

## Verifikasi setelah Backend menerapkan

Jangan SELECT `net.http_request_queue`. Antrean itu dapat memuat header `Authorization` sampai permintaan terkirim. Jangan salin `command` ke chat bila Anda tidak perlu; perintah hanya berisi SQL pembaca Vault, bukan nilai secret.

```sql
select jobid, jobname, schedule, active
from cron.job
where jobname = 'weather-refresh-hourly';
```

Harapan: satu baris, `schedule` = `7 * * * *`, `active` = true.

```sql
select start_time, end_time, status, return_message
from cron.job_run_details
where jobid = (
  select jobid from cron.job where jobname = 'weather-refresh-hourly'
)
order by start_time desc
limit 8;
```

Harapan: `status` succeeded kira-kira tiap jam pada menit 7. Run sukses saat secret belum ada juga succeeded, karena blok kembali tanpa HTTP. Itu belum membuktikan cache disegarkan.

```sql
select id, status_code, timed_out, error_msg, created
from net._http_response
order by created desc
limit 8;
```

Setelah secret Vault ada: dalam satu siklus ada baris `status_code` 200, `timed_out` false. `content` adalah JSON rute (`refreshed`, `providers`, `expires_at`) dan tidak memuat Bearer; tetap jangan tempel ke chat. `502` dengan `upsert_failed` berarti upsert gagal; itu bukan bukti jadwal.

```sql
select max(fetched_at) as newest_fetch, count(*) as rows
from public.weather_forecasts;
```

`newest_fetch` maju kira-kira tiap jam setelah job dan secret sama-sama hidup. Harapan operasional rute: 23 baris kabupaten/kota. Bandingkan dua pembacaan berjarak satu jam.

## Rollback

Cabut job. Jangan `drop extension` `pg_cron` atau `pg_net`. Jangan hapus baris `weather_forecasts`. Perintah yang sama ada sebagai komentar di akhir migrasi.

```sql
select cron.unschedule(jobid)
from cron.job
where jobname = 'weather-refresh-hourly';
```

Workflow GitHub tetap jalan sebagai cadangan 6 jam. Menerapkan ulang migrasi menjadwalkan job yang sama lagi.
